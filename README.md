# MedicalForms — დანიშნულების ფურცელი NIV-300-9/ა

Django საიტი, რომელიც ავსებს და ბეჭდავს ფორმას NIV-300-9/ა
(საქართველოს შრომის, ჯანმრთელობისა და სოციალური დაცვის მინისტრის 2009 წლის

> **ბეჭდვის ფორმა არ შეცვლილა.** წინა მხარე იბეჭდება `templates/MDFNew.docx`-დან
> (PDF-ად), უკანა მხარე `templates/mdf/niv-back.html`-დან. ეს ფაილები ხელუხლებელია.
> ცვლილებების შემდეგ ორივე ანაბეჭდი შედარდა ძველს და პიქსელ-პიქსელ იდენტურია.

## რა გაუმჯობესდა

### სამუშაოს სისწრაფე
- **Ctrl+S** — შენახვა (ახალ შაბლონზე იხსნება სახელის ფანჯარა, **Enter** ინახავს).
- **Shift + დაწკაპუნება** საათზე — იგივე საათი ერთდროულად სამივე დღეში.
- წამლის ძებნა: **↑ ↓** და **Enter**-ით არჩევა, **Esc** — დახურვა. ჯერ ჩანს წამლები,
  რომლებიც აკრეფილი ტექსტით *იწყება*; სია აღარ „ხტის“ სწრაფად აკრეფისას.
- თარიღი ხელით აკრეფისასაც ინახება (ადრე მხოლოდ კალენდრიდან არჩევისას).
- ახალი შაბლონის შენახვის შემდეგ რჩებით იმავე შაბლონზე — შეგიძლიათ მაშინვე დაბეჭდოთ.
- ძებნა შაბლონებში ასევე პირადი ნომრით; ძებნა შენარჩუნდება გვერდის განახლებისას.

### მონაცემების დაკარგვისგან დაცვა
- გაფრთხილება, თუ გვერდს ტოვებთ შეუნახავი ცვლილებებით.
- გაფრთხილება ბეჭდვისას, თუ ცვლილებები ჯერ შენახული არ არის
  (იბეჭდება ბოლოს შენახული ვერსია).
- თუ შენახვა ვერ მოხერხდა (მაგ. ზედმეტად გრძელი პირადი ნომერი), ჩნდება შეცდომის
  ტექსტი — ადრე ცვლილებები ჩუმად იკარგებოდა. ველებს აქვთ სიგრძის ლიმიტი.
- ბრჭყალები (`"`) წამლის სახელში ან დიაგნოზში აღარ აფუჭებს ჩანაწერს.
- ტექსტის ჩასმა მაუსით (Paste) ახლა ინახება.
- **Save As** აღარ ცვლის ორიგინალ შაბლონს — ქმნის მხოლოდ ასლს.
- შაბლონის წაშლა ითხოვს დადასტურებას.

### გასწორებული შეცდომები
- ძებნის შემდეგ „ბეჭდვა“ და „ქმედებები“ ღილაკები და წაშლა არ მუშაობდა — გასწორდა.
- მე-2+ გვერდზე ძებნისას „404“ შეცდომა — გასწორდა.
- არარსებული შაბლონის ბეჭდვისას სერვერის შეცდომა (500) — ახლა „ვერ მოიძებნა“.
- „დამახსოვრება“ შესვლისას არაფერს აკეთებდა — ახლა: მონიშნული → 14 დღე სისტემაში,
  მოუნიშნავი → გასვლა ბრაუზერის დახურვისას.
- არასწორი პაროლისას შეტყობინება არ ჩანდა — ახლა ჩანს.
- „პაროლის შეცვლა“ ღილაკი მუშაობს.

### უსაფრთხოება
- პაროლი და SECRET_KEY ამოღებულია კოდიდან → ინახება `.env` ფაილში (არ იტვირთება GitHub-ზე).
- `DEBUG` გამორთულია საიტზე (ადრე შეცდომისას ყველას უჩანდა კოდი და პარამეტრები).
- შესვლისას 5 არასწორი მცდელობის შემდეგ — 15 წუთიანი ბლოკი.

- დახურულია „open redirect“ შესვლის გვერდზე.
- Django 4.2.3 → 4.2.30 (ათობით უსაფრთხოების შესწორება).

## PythonAnywhere-ზე განახლება

> ყველა ბრძანება სრულდება PythonAnywhere-ის **Bash console**-ში
> (Dashboard → Consoles → Bash). ქვემოთ `~/MedicalForms` არის ძველი კოდის
> საქაღალდე — თუ თქვენთან სხვა სახელია, ჩაანაცვლეთ. ზუსტ გზას ნახავთ
> **Web** ტაბზე → *Source code*.

**1. სარეზერვო ასლი (აუცილებლად):**

```bash
cp -r ~/MedicalForms ~/MedicalForms-backup-$(date +%F)
```

```bash
mysqldump -u medf -h medf.mysql.pythonanywhere-services.com --no-tablespaces 'medf$MDF' > ~/mdf-backup-$(date +%F).sql
```

**2. ახალი კოდი:**

```bash
cd ~ && git clone -b claude/dazzling-cerf-tp4313 https://github.com/apkhadzeangio/New_MedF.git MedicalForms-new
```

**3. `.env` ფაილი** (საიდუმლო პარამეტრები):

```bash
cd ~/MedicalForms-new/src/MedicalForms && cp .env.example .env && python3 -c "import secrets; print(secrets.token_urlsafe(50))"
```

გახსენით `.env` (Files ტაბიდან) და ჩაწერეთ: `DJANGO_SECRET_KEY` = ზემოთ დაგენერირებული
სტრიქონი, `DB_PASSWORD` = MySQL-ის პაროლი (Databases ტაბი).

**4. ბიბლიოთეკები** (თუ საიტი virtualenv-ს იყენებს — ჯერ `workon <სახელი>`;
virtualenv-ის სახელი ჩანს Web ტაბზე):

```bash
cd ~/MedicalForms-new && pip install -r requirements/prod.txt
```

**5. შემოწმება და სტატიკური ფაილები:**

```bash
cd ~/MedicalForms-new/src/MedicalForms && python manage.py check && python manage.py migrate && python manage.py collectstatic --noinput
```

**6. გადართვა:** Web ტაბზე *Source code* და *Working directory* შეცვალეთ
`~/MedicalForms-new/src/MedicalForms`-ზე, WSGI ფაილში — `path`-იც იმავეზე
(ან ძველი საქაღალდე გადაარქვით და ახალს დაარქვით `MedicalForms`).
*Static files* ჩანაწერში `/static/` → `.../src/MedicalForms/staticfiles`.
დააჭირეთ **Reload**.

**7. HTTPS (რეკომენდებული):** Web ტაბზე ჩართეთ **Force HTTPS**, შემდეგ `.env`-ში
`DJANGO_HTTPS=1` და ისევ **Reload**.

**დაბრუნება ძველზე**, თუ რამე არ მუშაობს: Web ტაბზე გზები დააბრუნეთ ძველ
საქაღალდეზე და Reload. შეცდომის მიზეზს ნახავთ Web ტაბზე → *Error log*.

### Django 5.2 (არასავალდებულო)
Django 4.2-ის მხარდაჭერა დასრულდა 2026 წლის აპრილში. კოდი ტესტირებულია Django
5.2 LTS-ზეც (მხარდაჭერა 2028 წლამდე), მაგრამ მას სჭირდება MySQL 8.0+. შეამოწმეთ
MySQL console-ში `SELECT VERSION();` — თუ 8.x-ია, `requirements/prod.txt`-ში
ჩაწერეთ `Django==5.2.19`, გაუშვით `pip install -r requirements/prod.txt` და Reload.
